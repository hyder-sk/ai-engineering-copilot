▸ Phase 2 — Project Analyzer (RAG)

Click to expand Done

Big idea: You give a folder, not a string. The system loads files, chunks them, embeds them, finds the pieces most related to your question, then runs a structured analysis on that context. Still not a tool-using agent.

1

Repo path

Default fixture: NestJS app with a slow /users endpoint.

workspace/fixtures/slow-users-endpoint
↓
2

Document loader

Walk disk → each file becomes a LangChain Document (text + metadata.path).

loadRepoDocuments() → documentsLoaded: 6

↓
3

Text splitter

Large files → overlapping chunks. Small fixture ≈ 1 chunk per file.

splitCodeDocuments() → chunksIndexed: 6

↓

Embeddings + vector store

Each chunk → number vector via OpenAI embeddings, stored in RAM.

Embed the user question → find nearest chunks (similarity search).

▸ Phase 3 — Tools + Agent Loop

Click to expand Done

Big idea: The LLM chooses tools (search, read, test, git…) in a loop until it can answer. This is the first real agent behavior — still before LangGraph.

1

Question + workspace sandbox

Agent is scoped to a folder. Tools cannot read outside that root.

runCodingAgent({ workspaceRoot, question })
↓
2

Bind tools to the chat model

OpenAI receives tool schemas. Model may return tool_calls instead of plain text.

createChatModel().bindTools(createWorkspaceTools(root))
list_files read_file search_code run_tests run_linter git_diff git_log
↓
3

Agent loop

While model returns tool_calls → execute each tool → append ToolMessage → call model again.

LLM → tool_calls → tools.run → ToolMessage → LLM → … → final answer
agent/run-coding-agent.ts maxIterations default 8
↓
4

Final answer

When there are no more tool_calls, content is the answer (with file path citations).

npm run phase3

▸ Phase 1 vs 2 vs 3

Click to expand Reference

Differences

  • Phase 1: you paste code → one LLM call
  • Phase 2: folder → RAG retrieve → one LLM call
  • Phase 3: LLM picks tools in a loop until done
  • Both 1–2: fixed pipelines (chains)
  • Phase 3: first agent loop (still not LangGraph)

Fresher takeaway

  • Chain = fixed pipeline (Phase 1–2)
  • RAG = retrieve context, then chain (Phase 2)
  • Tool calling = model requests a function with args
  • Agent loop = think → act → observe → repeat (Phase 3)
  • LangGraph = explicit state machine for agents (Phase 5+)

▸ Glossary (for freshers)

Click to expand Reference
LCEL
LangChain Expression Language — connect steps with .pipe() (prompt → model → parser).
Prompt template
A message recipe with holes like {code} that get filled at runtime.
Zod schema
TypeScript-friendly shape definition. Used so the LLM returns valid structured JSON.
Document
LangChain object: file text (pageContent) + metadata (path, etc.).
Chunk
A smaller piece of a document so embeddings and prompts stay manageable.
Embedding
A list of numbers representing meaning. Similar text → nearby vectors.
Vector store
Database (here: in-memory) that stores embeddings and supports similarity search.
RAG
Retrieval-Augmented Generation — find relevant text first, then ask the LLM.
Tool calling
The model returns a structured request to run a named tool with arguments (not just text).
ToolMessage
Message that sends a tool’s result back into the chat history for the next LLM turn.
Agent loop
Repeat: model decides → tool runs → observation → model decides again, until a final answer.
N+1 query
Fetch a list, then fetch related data once per item in a loop (slow).
